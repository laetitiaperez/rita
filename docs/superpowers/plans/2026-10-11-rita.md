# Rita Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Une app macOS qui transforme une image en brush Krita (pointe + preset `.kpp` + `.bundle`) avec des courbes de pression éditables et un aperçu de trait.

**Architecture:** Swift Package à deux cibles. `RitaCore` (bibliothèque, Foundation/CoreGraphics/ImageIO/CryptoKit seulement, jamais AppKit ni SwiftUI) contient tout le métier : image, pointe, courbes, réglages, XML du preset, blocs PNG, `.kpp`, zip `.bundle`, simulation du trait — testé par `swift test`. `Rita` (exécutable SwiftUI) n'est que de la présentation. `scripts/bundle.sh` assemble `Rita.app`.

**Tech Stack:** Swift 6.4 + Xcode (actif via `xcode-select`), SwiftPM, Swift Testing (`import Testing`), SwiftUI, ImageIO, CoreGraphics, CryptoKit (`Insecure.MD5`), Foundation (`NSData.compressed(using: .zlib)`).

**Spec:** `docs/superpowers/specs/2026-10-11-rita-design.md` · **Notes de format :** `NOTES.md` · **Référence :** `docs/reference/j)_WaterC_Flat_Decay_Tilt.kpp`

**Code à reprendre :** `../Baguette` (même machine, `/Users/laetitiaperez/Claude Code/Baguette`) — `Sources/WandCore/RGBAImage.swift`, `ImageFile.swift` et leurs tests, `scripts/bundle.sh`, `scripts/make-icon.swift`, `.github/workflows/ci.yml` et `release.yml`, `.gitignore`.

## Global Constraints

- `swift-tools-version: 6.0` ; `platforms: [.macOS(.v14)]` ; aucune dépendance externe.
- **Pas** de `-plugin-path` / `unsafeFlags` dans `Package.swift` (Xcode est installé ; `swift test` fonctionne tel quel).
- `RitaCore` n'importe jamais AppKit ni SwiftUI.
- Pixels : RGBA8 **non prémultipliés**, sRGB, origine en haut à gauche, rangée par rangée.
- Courbes : points dans [0,1], format texte Krita `x,y;x,y;` (6 décimales max, `;` final).
- Version du preset : bloc `tEXt` `version` = `2.2` ; XML sous le bloc `zTXt` `preset`.
- Bundle : `mimetype` = `application/x-krita-resourcebundle`, première entrée du zip, stockée.
- Textes d'interface en français, exactement ceux de la spec (« Impossible de lire cette image »,
  « Dans Krita : Paramètres › Gérer les ressources › Importer un bundle »…).
- Bundle identifier `fr.laetitiaperez.rita` ; licence MIT (fichier `LICENSE`, auteur Laetitia Perez).
- Commit **et `git push`** à la fin de chaque tâche ; messages en français, terminés par
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Toute décision non écrite dans la spec → une ligne dans `NOTES.md`, section « Décisions ».

## Review Focus

1. **Grandes photos (24 Mpx)** : l'ouverture et chaque recalcul de pointe restent fluides → l'image source est réduite à 2048 px à l'ouverture. Test dans Tâche 1 (`loadDownscales`).
2. **Image qui a déjà de la transparence** (PNG détouré, par exemple par Baguette) : le seuil ne doit jamais rendre opaque un pixel transparent. Test dans Tâche 6 (`keepsExistingAlpha`).
3. **Nom de brush avec accents, `&`, `"`, `/`, emoji** : le XML reste valide (échappement de l'attribut `name`) et les noms de fichiers du bundle sont assainis mais gardent les accents. Tests dans Tâche 3 (`escapesName`) et Tâche 5 (`sanitizesNames`).
4. **Points de courbe glissés l'un sur l'autre** (même x) ou hors du cadre : la courbe reste valide (x strictement croissants, bornés, extrémités 0 et 1 présentes). Test dans Tâche 2 (`duplicateXKeepsLast`, `clampsAndKeepsEnds`).
5. **Photos avec orientation EXIF, niveaux de gris, 16 bits** : chargées dans le bon sens et en RGBA8. Tests repris de Baguette dans Tâche 1.
